# 初始版本 v14.1.0b3 / v5.0.3（2026-10-26）

三端（服务端 Manager、面板 Panel、客户端 App）的首个二开发布版本。
**对比基线**（各自的上游 fork 点）：

| 端 | 上游基线 | 相对官方改动 |
| --- | --- | --- |
| Manager | `hiddify/Hiddify-Manager@9c5e2229` | 32 个提交 / 40 个文件 / +2258 −586 |
| Panel | `hiddify/hiddifypanel@81456486` | 17 个提交 / 47 个文件 / +1351 −137 |
| App | `hiddify/hiddify-app@4b99aa68` | 45 个提交 / 80 个文件 / +3170 −1357 |

一句话概括：**把"安装 / 更新 / 回退 / 版本检查"整条链路从官方收回自己 fork**，
并修掉一批上游遗留问题（登录循环、静默失败、内存与启动性能、Windows 窗口与托盘）。

---

## 1. 最重要的变化：更新链路不再回到官方

这是本版本的核心。官方版本里，"面板点更新"在非 git 部署时会下载官方 release 包，
面板本体则从官方 PyPI 安装 —— 二开代码会被整体覆盖。

| 场景 | 官方行为 | 本版本 |
| --- | --- | --- |
| 更新源 | `hiddify/Hiddify-Manager`（main / beta / dev） | 只读本 fork 的 `dev-custom` |
| 版本查询 | GitHub API 查官方 releases | 查本 fork 的 releases（`HIDDIFY_MANAGER_REPO`） |
| 面板安装 | `uv pip install hiddifypanel`（官方 PyPI） | 从 `xgs87762GH/hiddifypanel` 源码构建安装 |
| zip 模式更新 | 官方 latest release 的 `hiddify-manager.zip` | 本 fork 同 tag 的 `hiddify-manager.zip` |
| 回退 / 降级 | 官方 PyPI 版本 + 官方 zip | 本 fork 源码 + 本 fork 最近的 release |
| 可选版本列表 | PyPI 上所有官方版本 | 本 fork 的 tag 列表 |
| git checkout | 只警告"请自行 git pull" | 从自身 remote `fetch` + `merge --ff-only` |

配套改动：

- `switch_to_fork.sh`：官方安装 → fork checkout，幂等，默认 `dev-custom`。
- 新增环境变量统一入口：`HIDDIFY_GITHUB_USER`、`HIDDIFY_MANAGER_REPO`、`HIDDIFY_PANEL_REPO`、`HIDDIFY_MANAGER_BRANCH`。
- release 包现在包含面板子模块，并排除 `.git*`（之前 zip 里面板目录是空的）。

> 仍然指向官方的地方是**故意保留**的，不影响二开：`packages.lock` 里的上游核心二进制
> （Xray / sing-box / mihomo 等）、用户端 UI 的官方 `gh-pages` 预构建包、v8 老库迁移包。

## 2. 服务端 Manager

**更新与安装**

- git checkout 支持原地升级（备份 → `fetch` → `ff-only` → 子模块 → `make build`），不再要求手工操作。
- zip 安装模式统一从 fork 的 `dev-custom` 取安装脚本，不再按 main/beta/dev 分支分散。
- 小内存 VPS 直接安装**预构建的管理端 UI**，不再现场编译（编译需要 ~1.2 GB 内存）。
- 下载的 release 包和脚本都带版本校验，失败即报错，不再静默降级。

**稳定性**

- 生成的配置先校验，通过后才重载 core 与 xray（之前可能带着坏配置重启）。
- 迁移残留的 systemd unit 停不掉时，回收其进程，避免占着 80/443。
- WARP 只改端点端口，不再动其它配置；`app.cfg` 占位密钥自愈；`make debug` 可用。
- 失败的服务步骤不再被报成"成功"。
- Redis 加内存上限与 `allkeys-lru` 淘汰，防止小机器被缓存撑爆。

## 3. 面板 Panel

| 问题 | 官方行为 | 本版本 |
| --- | --- | --- |
| 登录重定向 | 部分情况下登录后死循环 | 修复，并清掉类型错误 |
| `allowInsecure` | 订阅链接里无条件开启 | 按 Xray 核心版本门控 |
| 后台任务 | 与请求共用 session，偶发脏读 | 独立数据库 session |
| 网络受限 | 拿不到数据也一直等 | 超时快速失败 |

| 列表页 | 加载失败/无数据显示为空白 | 统一空状态组件 + 错误提示；域名页区分"空"与"无匹配" |

| 版本检查 | 查官方 release，官方版本号更高就标"过时" | 查本 fork 的 release |

## 4. 客户端 App（5.0.3）

**Windows**

- 单实例检测修正（不再重复启动、不再吞错误提示）。
- 启动时窗口先不显示，等首帧可绘制后再显示（消除白屏）。
- 混合 DPI 多显示器下恢复窗口位置；窗口重建后正确重绘。
- 托盘改为用当前值构建，不在 provider 更新中刷新（修复托盘状态滞后）。
- 安装包与可执行文件放在同一目录；MSIX 版本 5.0.3.0。

**性能**

- 启动并行化：app info / 偏好设置 / 翻译并发加载，配置修复放后台。
- 复用 HTTP client，多个 IP 探测源竞速，去掉每请求的 TCP 探测。
- 代理列表合并 url-test 突发结果后再排序；测试中隔离 tile 重绘。

**修复**

- 核心启动失败会明确上报，不再静默重试；TUN 模式下重启核心可恢复；未知状态不再卡死。
- 订阅 URL 精确匹配，取消孤儿请求；损坏配置在解析前修复。
- 设置保存失败会提示；统计溢出、连接按钮反馈、列表空/错误状态均已修。
- `app.log` 保留异常与其调用栈。

**UI / 测试**

- 首页与外壳支持宽屏；连接按钮按可用空间自适应。
- 新增布局 token、首页列数、网格数量、设置页与代理页测试。

## 5. 已知限制

- 本版本是**预发布**（tag 含 `b`）：`release` 模式的服务器不会把它当成正式版；正式发版请打 `v14.1.0`。
- 三个仓库都依赖 GitHub Actions 出包，fork 需在 `Settings → Actions` 允许运行。
- 客户端 CI 需要 Apple / Android / Windows 签名密钥；fork 上没有这些密钥时，
  构建产物为空，Release 只带说明文字，安装包需本地构建（见仓库内的 Windows 打包记录）。
- 面板仍硬依赖 MySQL 与 Redis，SQLite / fakeredis 跑不通（上游约束）。

## 6. 升级方式

```bash
# 已是 fork checkout 的服务器
cd /opt/hiddify-manager && bash scripts/update.sh

# 还是官方安装的服务器：先转 fork
bash <(curl -sSL https://raw.githubusercontent.com/xgs87762GH/Hiddify-Manager/dev-custom/scripts/switch_to_fork.sh)
```
